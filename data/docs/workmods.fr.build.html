Création

Créer un mod

Un mod est un dossier. Son contenu est exactement ce que verra le SDK du jeu, plus un manifeste optionnel workmod.json.

neon-ui/
├── workmod.json
├── neon-ui.bundle
└── bundles/
    └── shared.bundle

Le manifeste

À la publication, le client n'exige que name et version, mais id, game_id et les champs de compatibilité permettent au validateur de rejeter un paquet qui ne pourra pas tourner sur la cible.

ChampSignification
idIdentifiant stable du mod. Généré une fois, jamais modifié entre versions.
game_idJeu cible. Par défaut, le profil default.
name, versionNom et version. Le tag de release devient v<version>.
author, descriptionTexte libre affiché dans le catalogue.
entry_assetNom d'asset par défaut facultatif que le jeu peut charger.
bundlesChemins explicites des bundles, relatifs à la racine du mod. Recommandé quand les noms sont ambigus.
engine, sdkunity pour le SDK actuel.
unity_versionVersion minimale d'Unity pour laquelle le mod a été compilé.
platformswindows, linux, macos, android, ios.
min_client_version, min_sdk_versionClient et SDK les plus anciens capables d'installer ou de charger le mod.
tagsChaînes pour la recherche.
 
{
  "id": "a1b2c3d4",
  "game_id": "space-rangers",
  "name": "Neon UI",
  "version": "1.2.0",
  "author": "your-handle",
  "description": "Neon HUD replacement for the tactical screen.",
  "entry_asset": "NeonHud",
  "bundles": ["neon-ui.bundle", "bundles/shared.bundle"],
  "engine": "unity",
  "unity_version": "2021.3",
  "platforms": ["windows", "linux", "macos"],
  "tags": ["ui", "hud"]
}

Format du contenu

  • Les AssetBundles sont le format recommandé : ils fonctionnent avec Mono et IL2CPP sur toutes les plateformes. Compile un bundle par plateforme — il n'est pas portable entre elles.
  • Utilise ChunkBasedCompression (LZ4). Les bundles LZMA doivent être décompressés en entier et causent souvent des échecs sur Android.
  • Place les dépendances (bundles partagés, textures, shaders) dans le mod. Le SDK charge tous les bundles d'un mod avant de résoudre les assets.
  • Les Addressables fonctionnent car ils produisent des AssetBundles ; inclus les fichiers de bundle compilés du dossier de la plateforme.
  • Les DLL ne se chargent qu'avec le backend de script Mono. Considère-les comme du code totalement fiable.
using UnityEditor;
using UnityEngine;

public static class WorkmodsBundleBuilder
{
    [MenuItem("Workmods/Build Mod Bundle")]
    public static void Build()
    {
        var builds = new[]
        {
            new AssetBundleBuild
            {
                assetBundleName = "neon-ui.bundle",
                assetNames = new[] { "Assets/ModContent/NeonHud.prefab" }
            }
        };

        BuildPipeline.BuildAssetBundles(
            "Build/Mod", builds,
            BuildAssetBundleOptions.ChunkBasedCompression,
            BuildTarget.StandaloneWindows64);
    }
}

CLI d'auteur

L'éditeur de bureau suffit, mais les mêmes outils existent en terminal et en CI. Chaque commande sort avec un code non nul en cas d'erreur et accepte --json pour une sortie lisible par machine.

# créer un dossier avec un workmod.json prérempli
python -m workmods init neon-ui --name "Neon UI" --game space-rangers --author your-handle

# vérifier les champs requis, les bundles et le contenu manquant
python -m workmods validate neon-ui

# construire le ZIP de release et afficher son SHA-256
python -m workmods pack neon-ui --out dist/neon-ui.zip

# rouvrir le ZIP et vérifier contenu et empreinte
python -m workmods validate-package dist/neon-ui.zip --sha256 <digest>

# vérifier la compatibilité avec une cible précise
python -m workmods validate-package dist/neon-ui.zip \
  --engine unity --unity-version 2022.3 --platform windows --platform linux

Dans l'éditeur

  1. Author Studio → Connexion via GitHub, puis Nouveau dépôt pour créer un dépôt public avec un commit initial (ou en choisir un existant).
  2. Créer la fiche du mod : l'identifiant est généré, renseigne le jeu cible, le nom, la version, l'auteur, la description, l'icône et la bannière, les tags et le dossier des fichiers. Un workmod.json dans ce dossier préremplit les champs vides.
  3. Enregistrer le mod écrit un brouillon local dans le dossier d'installation du jeu, pour l'installer et le tester en jeu avant publication.
Propreté L'empaquetage ignore .devers_meta.json, .git, __pycache__, .DS_Store, Thumbs.db et .workmods-disabled, mais mieux vaut garder le dossier propre.

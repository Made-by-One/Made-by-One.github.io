发布

发布就是一次 pull request。你只需要 GitHub 账号；不需要懂 git、不需要注册表写权限，也不需要服务器。

  1. 客户端把模组文件夹打包为 ZIP（根目录就是该文件夹，没有外层目录）并计算 SHA-256。
  2. 所有文件以及 icon.png / banner.png 都会提交到你的模组仓库。
  3. 创建发行版 v<version>，并附加 <modId>.zip。
  4. pull request 会添加 submissions/<game_id>/<mod_id>.json，包含元数据、下载地址、摘要与你的登录名。
  5. Validate Submission 检查路径、id、版本、哈希与发行地址。维护者审核后合并。
  6. Rebuild Mod Registry 根据所有提交文件重建 registry.json。玩家在下次刷新目录后看到该模组。

版本与更新

  • 版本号可自由书写，但不能含空格和斜杠：1.0.0、1.2.0、2.0.0-beta.1。标签始终为 v<version>。
  • 用同一版本再次发布会复用该发行版并替换其资源。
  • 更新时修改模组、提升版本并发布——pull request 会更新同一个提交文件，玩家只保留一条记录。请先关闭该模组之前仍打开的 pull request。
  • Unpublish 会发起删除提交文件的 pull request。你的仓库、文件和发行版仍然在线，已安装的玩家保留本地副本。

限制

限制数值
通过 GitHub Contents API 上传的单个文件应明显低于 100 MB——该 API 不是 CDN
发行 ZIP最大 2 GB
模组 id[a-z0-9][a-z0-9._-]{1,63}
标签最多 20 个短字符串
校验和64 个小写十六进制字符，客户端下载后校验

发布前请确认：game_id 与游戏完全一致，bundle 针对正确平台构建，版本已提升且模组 id 未变，模组已在本地测试，文件夹中不含密钥或未授权的素材。

Публікація

Публікація — це pull request. Потрібен акаунт GitHub; знання git, прав запису до реєстру чи власного сервера не потрібно.

  1. Клієнт пакує теку мода в ZIP (корінь — сама тека, без обгортки) і рахує SHA-256.
  2. Усі файли, а також icon.png / banner.png, комітяться у ваш репозиторій мода.
  3. Створюється реліз v<version>, до нього прикріплюється <modId>.zip.
  4. Pull request додає submissions/<game_id>/<mod_id>.json з метаданими, посиланням на завантаження, дайджестом і вашим логіном.
  5. Validate Submission перевіряє шлях, id, версію, хеш і посилання на реліз. Мейнтейнер дивиться та зливає.
  6. Rebuild Mod Registry перезбирає registry.json з усіх файлів заявок. Гравці бачать мод після наступного оновлення каталогу.

Версії та оновлення

  • Версія — вільний рядок без пробілів і слешів: 1.0.0, 1.2.0, 2.0.0-beta.1. Тег завжди v<version>.
  • Повторна публікація тієї самої версії використовує той самий реліз і замінює його asset.
  • Щоб оновити мод, відредагуйте його, підніміть версію та опублікуйте — pull request оновить той самий файл заявки, тож у гравців залишиться один запис. Спершу закрийте старіший відкритий pull request щодо цього мода.
  • Unpublish відкриває pull request з видаленням файлу заявки. Репозиторій, файли та релізи залишаються онлайн, а в наявних гравців лишається локальна копія.

Контрольна сума64 hex-символи в нижньому регістрі, клієнт звіряє після завантаження

Перед публікацією: game_id точно збігається з грою, бандли зібрані під потрібну платформу, версія піднята, а id мода не змінився, мод перевірено локально, а всередині немає секретів і неліцензованих матеріалів.

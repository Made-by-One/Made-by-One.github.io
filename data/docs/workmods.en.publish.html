Release

Publishing

Publishing is a pull request. You need a GitHub account; you do not need git knowledge, write access to the registry or a server.

  1. The client zips the mod folder (root = the folder itself, no wrapper directory) and computes its SHA-256.
  2. Every file, plus icon.png / banner.png, is committed to your mod repository.
  3. A release v<version> is created and <modId>.zip is attached to it.
  4. A pull request adds submissions/<game_id>/<mod_id>.json with the metadata, download URL, digest and your login.
  5. Validate Submission checks the path, id, version, hash and release URL. A maintainer reviews and merges.
  6. Rebuild Mod Registry regenerates registry.json from every submission file. Players see the mod after the next refresh.

Versions and updates

  • Versions are free-form without spaces or slashes: 1.0.0, 1.2.0, 2.0.0-beta.1. The tag is always v<version>.
  • Publishing the same version again reuses the release and replaces its asset.
  • To update, edit the mod, bump the version and publish — the pull request updates the same submission file, so players keep one entry. Close an older open pull request for that mod first.
  • Unpublish opens a pull request that deletes the submission file. Your repository, files and releases stay online and existing players keep their copy.

Mod id[a-z0-9][a-z0-9._-]{1,63}
TagsList of at most 20 short strings

Before publishing: game_id matches the game exactly, bundles are built for the right platform, the version is bumped while the mod id stays the same, the mod was tested locally, and nothing secret or unlicensed is inside the folder.

Publicación

Publicar es un pull request. Necesitas una cuenta de GitHub; no necesitas saber git, ni permisos de escritura en el registro, ni un servidor.

  1. El cliente comprime la carpeta del mod en un ZIP (raíz = la propia carpeta, sin carpeta contenedora) y calcula su SHA-256.
  2. Todos los archivos, más icon.png / banner.png, se confirman en tu repositorio del mod.
  3. Se crea el release v<version> y se adjunta <modId>.zip.
  4. Un pull request añade submissions/<game_id>/<mod_id>.json con los metadatos, la URL de descarga, el digest y tu usuario.
  5. Validate Submission comprueba ruta, id, versión, hash y URL del release. Un mantenedor revisa y fusiona.
  6. Rebuild Mod Registry regenera registry.json a partir de todos los archivos de envío. Los jugadores ven el mod tras la siguiente actualización del catálogo.

Versiones y actualizaciones

  • La versión es texto libre sin espacios ni barras: 1.0.0, 1.2.0, 2.0.0-beta.1. La etiqueta siempre es v<version>.
  • Volver a publicar la misma versión reutiliza el release y reemplaza su asset.
  • Para actualizar, edita el mod, sube la versión y publica: el pull request actualiza el mismo archivo de envío, así que los jugadores mantienen una sola entrada. Cierra antes cualquier pull request abierto de ese mod.
  • Unpublish abre un pull request que elimina el archivo de envío. Tu repositorio, archivos y releases siguen en línea, y los jugadores actuales conservan su copia local.

Límites

LímiteValor
Archivo individual vía GitHub Contents APIBastante por debajo de 100 MB: la API no es una CDN
ZIP del releaseHasta 2 GB
Id del mod[a-z0-9][a-z0-9._-]{1,63}
EtiquetasLista de 20 cadenas cortas como máximo
Suma de comprobación64 caracteres hex en minúsculas; el cliente la verifica tras la descarga

Antes de publicar: el game_id coincide exactamente con el juego, los bundles están compilados para la plataforma correcta, la versión está subida y el id del mod no cambió, el mod se probó en local y no hay secretos ni material sin licencia dentro de la carpeta.

Building a mod

A mod is a folder. Its contents are exactly what the game's SDK will see, plus an optional workmod.json manifest.

neon-ui/
├── workmod.json
├── neon-ui.bundle
└── bundles/
    └── shared.bundle

The manifest

Only name and version are required by the client when publishing, but id, game_id and the compatibility fields let the validator reject a package that cannot run on the target machine.

FieldMeaning
idStable mod id. Generated once, never changed between versions.
game_idTarget game. Defaults to the game's default profile.
name, versionDisplay name and version. The release tag becomes v<version>.
author, descriptionFree text shown in the catalog.
entry_assetOptional default asset name the game can load.
bundlesExplicit bundle paths, relative to the mod root. Recommended when names are ambiguous.
engine, sdkunity for the current SDK.
unity_versionMinimum Unity version the mod was built for.
platformswindows, linux, macos, android, ios.
min_client_version, min_sdk_versionOldest client and SDK that can install or load the mod.
tagsSearchable strings.
 
{
  "id": "a1b2c3d4",
  "game_id": "space-rangers",
  "name": "Neon UI",
  "version": "1.2.0",
  "author": "your-handle",
  "description": "Neon HUD replacement for the tactical screen.",
  "entry_asset": "NeonHud",
  "bundles": ["neon-ui.bundle", "bundles/shared.bundle"],
  "engine": "unity",
  "unity_version": "2021.3",
  "platforms": ["windows", "linux", "macos"],
  "tags": ["ui", "hud"]
}

Content format

  • AssetBundles are the recommended format: they work with Mono and IL2CPP on every platform. Build one bundle per platform — a bundle is not portable between them.
  • Use ChunkBasedCompression (LZ4). LZMA bundles must be fully decompressed and are a common cause of Android failures.
  • Ship dependencies (shared bundles, textures, shaders) inside the mod. The SDK loads every bundle of a mod before resolving assets.
  • Addressables work because they produce AssetBundles; ship the built bundle files from the platform folder.
  • DLL assemblies only load on the Mono scripting backend. Treat them as fully trusted code.
using UnityEditor;
using UnityEngine;

public static class WorkmodsBundleBuilder
{
    [MenuItem("Workmods/Build Mod Bundle")]
    public static void Build()
    {
var builds = new[]
{
    new AssetBundleBuild
    {
        assetBundleName = "neon-ui.bundle",
        assetNames = new[] { "Assets/ModContent/NeonHud.prefab" }
    }
};

BuildPipeline.BuildAssetBundles(
    "Build/Mod", builds,
    BuildAssetBundleOptions.ChunkBasedCompression,
    BuildTarget.StandaloneWindows64);
    }
}

Author CLI

The desktop editor is enough, but the same helpers run from a shell or CI. Every command exits non-zero on errors and accepts --json for machine-readable output.

# scaffold a folder with a filled-in workmod.json
python -m workmods init neon-ui --name "Neon UI" --game space-rangers --author your-handle

# check required fields, listed bundles and missing content
python -m workmods validate neon-ui

# build the release ZIP and print its SHA-256
python -m workmods pack neon-ui --out dist/neon-ui.zip

# reopen the ZIP and verify contents and digest
python -m workmods validate-package dist/neon-ui.zip --sha256 <digest>

# check compatibility against a concrete target
python -m workmods validate-package dist/neon-ui.zip \
  --engine unity --unity-version 2022.3 --platform windows --platform linux

In the editor

  1. Author Studio → Login via GitHub, then New Repo to create a public repository with an initial commit (or pick an existing one).
  2. Create a mod entry: the id is generated, fill in target game, name, version, author, description, icon and banner, tags and the files folder. A workmod.json in that folder pre-fills fields you left empty.
  3. Save Mod writes a local draft into the game's install folder, so you can install and test it in-game before publishing.
Keep clean Packaging skips .devers_meta.json, .git, __pycache__, .DS_Store, Thumbs.db and .workmods-disabled, but keep the folder tidy anyway.

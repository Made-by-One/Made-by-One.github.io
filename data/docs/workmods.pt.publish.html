Publicação

Publicar é um pull request. Você precisa de uma conta GitHub; não precisa de git, de permissão de escrita no registro nem de servidor.

  1. O cliente compacta a pasta do mod em ZIP (raiz = a própria pasta, sem pasta externa) e calcula o SHA-256.
  2. Todos os arquivos, mais icon.png / banner.png, são enviados ao seu repositório do mod.
  3. Um release v<version> é criado e <modId>.zip é anexado a ele.
  4. Um pull request adiciona submissions/<game_id>/<mod_id>.json com metadados, URL de download, digest e seu login.
  5. Validate Submission confere caminho, id, versão, hash e URL do release. Um mantenedor revisa e faz o merge.
  6. Rebuild Mod Registry regenera o registry.json a partir de todos os arquivos de envio. Os jogadores veem o mod após a próxima atualização do catálogo.

Versões e atualizações

  • A versão é texto livre, sem espaços nem barras: 1.0.0, 1.2.0, 2.0.0-beta.1. A tag é sempre v<version>.
  • Publicar a mesma versão de novo reutiliza o release e substitui seu asset.
  • Para atualizar, edite o mod, suba a versão e publique: o pull request atualiza o mesmo arquivo de envio, então os jogadores mantêm uma única entrada. Feche antes um pull request ainda aberto desse mod.
  • Unpublish abre um pull request que apaga o arquivo de envio. Seu repositório, arquivos e releases continuam online, e quem já instalou mantém a cópia local.

Limites

LimiteValor
Arquivo individual via GitHub Contents APIBem abaixo de 100 MB — a API não é uma CDN
ZIP do releaseAté 2 GB
Id do mod[a-z0-9][a-z0-9._-]{1,63}
TagsLista de no máximo 20 strings curtas
Checksum64 caracteres hex minúsculos, verificados pelo cliente após o download

Antes de publicar: o game_id corresponde exatamente ao jogo, os bundles foram compilados para a plataforma certa, a versão foi elevada e o id do mod não mudou, o mod foi testado localmente e não há segredos nem material sem licença na pasta.

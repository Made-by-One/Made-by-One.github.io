Публикация

Публикация — это pull request. Нужен аккаунт GitHub; знания git, прав записи в реестр или своего сервера не требуется.

  1. Клиент упаковывает папку мода в ZIP (корень — сама папка, без обёртки) и считает SHA-256.
  2. Все файлы, а также icon.png / banner.png, коммитятся в ваш репозиторий мода.
  3. Создаётся релиз v<version>, к нему прикрепляется <modId>.zip.
  4. Pull request добавляет submissions/<game_id>/<mod_id>.json с метаданными, ссылкой на скачивание, дайджестом и вашим логином.
  5. Validate Submission проверяет путь, id, версию, хеш и ссылку на релиз. Мейнтейнер смотрит и вливает.
  6. Rebuild Mod Registry пересобирает registry.json из всех файлов заявок. Игроки видят мод после следующего обновления каталога.

Версии и обновления

  • Версия — свободная строка без пробелов и слэшей: 1.0.0, 1.2.0, 2.0.0-beta.1. Тег всегда v<version>.
  • Повторная публикация той же версии переиспользует релиз и заменяет его asset.
  • Чтобы обновить мод, отредактируйте его, поднимите версию и опубликуйте — pull request обновит тот же файл заявки, поэтому у игроков останется одна запись. Сначала закройте более старый открытый pull request по этому моду.
  • Unpublish открывает pull request с удалением файла заявки. Репозиторий, файлы и релизы остаются онлайн, а у существующих игроков остаётся локальная копия.

Ограничения

ОграничениеЗначение
Отдельный файл через GitHub Contents APIЗаметно меньше 100 МБ — API не заменяет CDN
Релизный ZIPДо 2 ГБ
Id мода[a-z0-9][a-z0-9._-]{1,63}
ТегиСписок не длиннее 20 коротких строк
Контрольная сумма64 hex-символа в нижнем регистре, клиент сверяет после загрузки

Перед публикацией: game_id точно совпадает с игрой, бандлы собраны под нужную платформу, версия поднята, а id мода не изменился, мод проверен локально, а внутри нет секретов и нелицензированных материалов.

Doc 01 · Overview

Devers Workmods

Workmods is a universal mod manager for Unity games. It has three parts that share one contract — the registry entry — so a mod published once appears in every player's catalog, installs into the right folder and loads through the game's SDK without per-game work on our side.

PartWhat it does
Desktop client Python + PyQt6 app for players and authors: browse the catalog, install, update, enable or disable mods, and publish to your own GitHub repository.
Registry registry.json in the Workmods repository, rebuilt by GitHub Actions from one submission file per mod. Clients read it from raw.githubusercontent.com.
Unity SDK A single dependency-free C# file that scans the mods folder, lists installed mods and loads their AssetBundles.
  • Current version: 1.2b public beta, built for Windows x64, Linux x86_64 and macOS.
  • MIT licensed, no telemetry, no background services.
  • Mods live in the modder's own GitHub repository and are distributed through GitHub Releases. The client never writes to the shared registry — it opens a pull request.
Requirements

Requirements & dependencies

Release builds are self-contained: Python and PyQt6 are bundled, so players install nothing else. Running from source is only needed for development.

Prebuilt client

  • Windows 10/11 x64, Linux x86_64 (built on Ubuntu 22.04, runs on newer glibc) or macOS.
  • No Python, no Qt and no admin rights. On Linux, chmod +x once.
  • A network connection for the catalog. A GitHub account is required only for authoring and publishing.

Headless The author CLI (python -m workmods) imports no Qt, so it runs on a build machine or in CI without a display.

Unity SDK

  • C# 7.3 and Unity 2019.4 or newer; works with Mono and IL2CPP, but runtime DLL loading needs Mono.
  • No package manager and no assembly definition required — one file copied into Assets/.
  • AssetBundles work on every Unity platform; WebGL is not supported by the SDK.

Where things are stored

PathContents
~/.devers_workmods/config.jsonRegistry URL, language, GitHub token, game profiles
~/.devers_workmods/profiles.jsonMod profiles: enabled sets and settings presets
~/DeversMods/<game_id>/Default install directory of a game profile
<mods>/.workmods-disabled/Disabled mods, skipped by the SDK
<mods>/workmods.logSDK log, when file logging is on

The config directory can be moved with WORKMODS_CONFIG_DIR; the registry source with WORKMODS_REGISTRY_REPO and WORKMODS_REGISTRY_BRANCH.

Installation

Install & first launch

  1. Open the Releases page and download the archive for your system: Workmods-windows-x86_64.zip, Workmods-linux-x86_64.tar.gz or Workmods-macos.zip.
  2. Unpack it anywhere. The build is portable: state lives in your home folder, not next to the executable.
  3. Start Workmods.exe on Windows, ./Workmods on Linux (after chmod +x Workmods) or Workmods.app on macOS.
  4. On first launch the client fetches the registry, picks your system language and creates the default game profile.

The interface ships in six languages — English, Russian, German, Spanish, French and Chinese — and switches instantly in Settings. The catalog is read-only until you log in with GitHub; installing and updating mods never requires an account.

Updates Settings → Application Updates checks GitHub Releases, verifies SHA256SUMS and the detached signature when one is published, keeps a backup of the previous executable and can roll back if applying the update fails.
Daily use

The client

Four tabs cover the whole workflow: playing, managing what is installed, authoring and configuration.

TabWhat you do there
Catalog Search and filter mods by game, read the detail pane with cover, author, version and tags, then Install or Reinstall / Update. Refresh reloads the registry.
Installed See what is installed for the active profile, open the mod folder, enable or disable a mod, delete it, and save or apply mod profiles with settings presets.
Author Studio Log in with GitHub, create or pick a repository, write a mod entry, preview local drafts in the game and publish.
Settings Registry URL, interface language, active game, game profiles, config folder and application updates.

Installing requires one click and no account. Authoring is the only part that needs a GitHub login: the client opens a browser window and asks for the repo scope, which it uses to create a repository for your mod and open the registry pull request.

Configuration

Game profiles

One installation of Workmods manages mods for any number of Unity games. A profile is a record of { id, name, install_dir, sdk }; the registry only stores the game_id, so nothing is tied to one machine.

  1. Open Settings → Game Profiles and choose Add Game.
  2. Enter a Game ID in lower case (a-z, 0-9, ., _, -) — the exact value the game passes to WorkmodsSDK.Initialize.
  3. Set a display name and the install directory the game scans. Empty means ~/DeversMods/<game_id>.
  4. Pick the profile as the active game. Catalog and Installed both filter to it; All games shows everything.
Folder The default profile is called “Unassigned”, cannot be removed and keeps mods that do not declare a game_id. The Unity SDK defaults to Application.persistentDataPath/Workmods, so either point the profile at that folder or pass the profile's directory to Initialize.
Playing

Installing & managing mods

An install downloads the release asset named in the registry, verifies its SHA-256 when the registry has one, extracts it safely and only then swaps the folder. An interrupted download never leaves a half-written mod where the game can see it.

  1. Install extracts into <install_dir>/<modId> and writes .devers_meta.json with the registry metadata.
  2. Reinstall / Update replaces the existing folder with the version from the catalog.
  3. Disable moves the folder to .workmods-disabled/; Enable moves it back. No manifest is edited and the SDK ignores hidden folders.
  4. Delete removes the mod folder. The client refuses paths outside the profile's install directory.

Profiles make switching painless: Installed → Mod Profile saves the current enabled/disabled set plus a settings object under a name, applies it later by moving folders on disk, and exports or imports it as portable JSON. That is how you keep, for example, a vanilla-plus set and a heavily modded set for the same game.

Authoring

Building a mod

A mod is a folder. Its contents are exactly what the game's SDK will see, plus an optional workmod.json manifest.

neon-ui/
├── workmod.json
├── neon-ui.bundle
└── bundles/
    └── shared.bundle

The manifest

Only name and version are required by the client when publishing, but id, game_id and the compatibility fields let the validator reject a package that cannot run on the target machine.

FieldMeaning
idStable mod id. Generated once, never changed between versions.
game_idTarget game. Defaults to the game's default profile.
name, versionDisplay name and version. The release tag becomes v<version>.
author, descriptionFree text shown in the catalog.
entry_assetOptional default asset name the game can load.
bundlesExplicit bundle paths, relative to the mod root. Recommended when names are ambiguous.
engine, sdkunity for the current SDK.
unity_versionMinimum Unity version the mod was built for.
platformswindows, linux, macos, android, ios.
min_client_version, min_sdk_versionOldest client and SDK that can install or load the mod.
tagsSearchable strings.

Content format

  • AssetBundles are the recommended format: they work with Mono and IL2CPP on every platform. Build one bundle per platform — a bundle is not portable between them.
  • Use ChunkBasedCompression (LZ4). LZMA bundles must be fully decompressed and are a common cause of Android failures.
  • Ship dependencies (shared bundles, textures, shaders) inside the mod. The SDK loads every bundle of a mod before resolving assets.
  • Addressables work because they produce AssetBundles; ship the built bundle files from the platform folder.
  • DLL assemblies only load on the Mono scripting backend. Treat them as fully trusted code.
using UnityEditor;
using UnityEngine;

public static class WorkmodsBundleBuilder
{
    [MenuItem("Workmods/Build Mod Bundle")]
    public static void Build()
    {
        var builds = new[]
        {
            new AssetBundleBuild
            {
                assetBundleName = "neon-ui.bundle",
                assetNames = new[] { "Assets/ModContent/NeonHud.prefab" }
            }
        };

        BuildPipeline.BuildAssetBundles(
            "Build/Mod", builds,
            BuildAssetBundleOptions.ChunkBasedCompression,
            BuildTarget.StandaloneWindows64);
    }
}

Author CLI

The desktop editor is enough, but the same helpers run from a shell or CI. Every command exits non-zero on errors and accepts --json for machine-readable output.

# scaffold a folder with a filled-in workmod.json
python -m workmods init neon-ui --name "Neon UI" --game space-rangers --author your-handle

# check required fields, listed bundles and missing content
python -m workmods validate neon-ui

# build the release ZIP and print its SHA-256
python -m workmods pack neon-ui --out dist/neon-ui.zip

# reopen the ZIP and verify contents and digest
python -m workmods validate-package dist/neon-ui.zip --sha256 <digest>

# check compatibility against a concrete target
python -m workmods validate-package dist/neon-ui.zip \
  --engine unity --unity-version 2022.3 --platform windows --platform linux

In the editor

  1. Author Studio → Login via GitHub, then New Repo to create a public repository with an initial commit (or pick an existing one).
  2. Create a mod entry: the id is generated, fill in target game, name, version, author, description, icon and banner, tags and the files folder. A workmod.json in that folder pre-fills fields you left empty.
  3. Save Mod writes a local draft into the game's install folder, so you can install and test it in-game before publishing.
Keep clean Packaging skips .devers_meta.json, .git, __pycache__, .DS_Store, Thumbs.db and .workmods-disabled, but keep the folder tidy anyway.
Release

Publishing

Publishing is a pull request. You need a GitHub account; you do not need git knowledge, write access to the registry or a server.

  1. The client zips the mod folder (root = the folder itself, no wrapper directory) and computes its SHA-256.
  2. Every file, plus icon.png / banner.png, is committed to your mod repository.
  3. A release v<version> is created and <modId>.zip is attached to it.
  4. A pull request adds submissions/<game_id>/<mod_id>.json with the metadata, download URL, digest and your login.
  5. Validate Submission checks the path, id, version, hash and release URL. A maintainer reviews and merges.
  6. Rebuild Mod Registry regenerates registry.json from every submission file. Players see the mod after the next refresh.

Versions and updates

  • Versions are free-form without spaces or slashes: 1.0.0, 1.2.0, 2.0.0-beta.1. The tag is always v<version>.
  • Publishing the same version again reuses the release and replaces its asset.
  • To update, edit the mod, bump the version and publish — the pull request updates the same submission file, so players keep one entry. Close an older open pull request for that mod first.
  • Unpublish opens a pull request that deletes the submission file. Your repository, files and releases stay online and existing players keep their copy.

Limits

For game developers

Unity SDK

unity-sdk/WorkmodsSDK.cs is a single, dependency-free C# file that scans a mods folder, exposes installed mods and loads their assets.

  1. Copy WorkmodsSDK.cs into your project, for example Assets/Workmods/.
  2. Decide where mods live. The client defaults to ~/DeversMods/<game_id>; the SDK defaults to Application.persistentDataPath/Workmods. Point the game profile at the folder your game scans, or pass modsRoot when you initialize.
  3. Initialize once, then load by mod id and asset name.
using Workmods;
using UnityEngine;

public class Mods : MonoBehaviour
{
    private void Awake()
    {
        WorkmodsSDK.Initialize(
            modsRoot: null,            // null → persistentDataPath/Workmods
            gameId: "space-rangers",   // reject mods for other games
            verboseLogging: true,
            writeLogToFile: true);     // <modsRoot>/workmods.log
    }
}

// load a prefab from an installed mod
var prefab = WorkmodsSDK.LoadAsset<GameObject>("a1b2c3d4", "NeonHud");
if (prefab != null) Instantiate(prefab);
MemberDescription
Initialize(...)Scan the folder. Safe to call repeatedly.
Rescan()Re-read the folder after an in-game install.
GetInstalledMods()Installed mods, filtered by gameId.
GetInstalledMod(id), IsInstalled(id)Lookup helpers, case-insensitive.
LoadAssetBundle(id, name)UnityEngine.Object or null; logs the reason on failure.
LoadAsset<T>(id, name)Typed variant, for example <GameObject>.
LoadBundles(mod)Load and cache every bundle of a mod, handling dependencies.
TryLoadAssembly(id, out asm)Mono only; returns false on IL2CPP.
UnloadAssetBundle(id), UnloadAll()Unload bundles — destroy instances first.
WorkmodsLog.OnLogPipe SDK messages into your own logger.
  • Everything runs on the main thread; do not load bundles from worker threads.
  • Disabled mods live in .workmods-disabled/ and are skipped automatically on the next scan.
  • Windows, macOS and Linux standalone are fully supported; Android needs LZ4 bundles; iOS works with AssetBundles installed by your own UI; consoles need platform packaging.
  • WebGL is not supported: it has no synchronous file access and needs an asynchronous loader.

Troubleshooting

SymptomCause and fix
Catalog is emptyRegistry request failed or the filter is set to a game without mods. Refresh, then switch to All games.
No mods folder at …Nothing installed yet, or the game scans a different folder than the profile. Set the profile directory or pass modsRoot.
Mod discovered but skippedgame_id mismatch with Initialize(gameId: …).
no AssetBundle foundThe folder has no .bundle, .unity3d or .bytes file and the manifest does not list bundles.
Asset loads but prefab is pinkShaders or textures sit in another bundle. Ship dependencies inside the mod and load all bundles.
Android The archive is corruptedRebuild the bundle with LZ4 compression.
GitHub API 401Token missing or expired — log out and log in again.
GitHub API 403 / 404Token lacks access to the target repository, or a rate limit. Re-login or pick another repository.
GitHub API 422Release tag rejected or a file too large. Bump the version and keep files well below 100 MB.
Pull request conflictsAnother open pull request changes the same mod file. Close the older one and publish again.
Mod never appears after mergeThe rebuild action failed. Open the repository's Actions → Rebuild Mod Registry and read the log.
Checksum mismatch for playersThe release asset changed after publishing. Publish again so the SHA-256 matches.
